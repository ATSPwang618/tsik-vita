# 月姬 Vita R3：日文、简体中文与统一主字体

本次实现用户确认的规格：首次启动与恢复默认设置选择简体中文；设置只有
“简体中文／日本語”，主动切换到日文后保存选择。R3 继承 R2 的素材解码边界
修复、内存预算和资源错误记录。这里记录离线验证，不代表 Vita 通关或实机验证。

## 字体

用户提供的 `arshanghaisonggbpro_lt.otf` 实际内部名称为“明朝金陵 Bold”，
字形为 TrueType outlines；按其实际格式存为 `assets/fonts/main.ttf`，文件内容
完整保留，不做字体转换。

- 主字体：6,249,992 字节。
- SHA-256：`0ebe4fac683355ea899a15a19f61bb3900135a424a8484ccf1758b73721eeef2`。
- 两种语言的剧情、动态 UI、历史文本、气泡文字共用此主字体策略。
- 日文剧情和系统文本的 2,759 个可见字符均可直接显示。
- 简体剧情和系统文本的 3,456 个可见字符中，只有“嗞、觍”需要补字。
- `fonts/fallback.otf` 仅保留这两个码点，大小 2,984 字节；来自 R2 原有简体字体。
- 原有 `exfont_nx01.bffnt` 保留，用于游戏特殊符号。

语言选项的图片标签已用提供字体重新绘制为两行、三种按钮状态。其他原本直接
绘制在图片里的标题、按钮、背景说明维持原有美术；替换动态字体不会自动改变
图片中的文字。共享图集内原有的非活动语言区域也保留原始坐标，避免影响
流程图、CG 等按原始编号读取的功能；它们不增加可选语言。

## 素材与包身份

- `script_text.mrg` 从 10 个块缩减为日文、简体各一对，共 4 个块；保留块字节完全一致。
- SYSMES 和按语言排列的控制帮助 UV 表均缩为两种语言。
- 20 个英文、繁体 UI 归档条目置为 `NOFILE.EXISTS`，原有归档条目编号不移动。
- 303 张剧情多语言图片裁出日文和简体；保留的 606 个区域逐像素比对通过。
- 非整除高度遵循生产解码器的 `top = height * language / 4`、`rows = height / 4` 规则。
- 移除独立英文、繁体电影、保存图标，并以新共享字体替换旧的 12 个字体目录。
- 更新启动清单、22 个 UI atlas 索引、16,601 条 stream 文件索引及其清单绑定。
- 新素材文件 16,764 个，不计清单本身；内容合计 3,884,337,696 字节，较 R2 减少 219,142,993 字节。
- 素材清单 SHA-256：`41fd21e6ba2b66205f88e4ccf0ba5beebaaf81420237768de8831d3102277e6d`。
- 构建标签：`tsukihime540-r3-ja-zc-font-20261031`。

R3 的正式 VPK 与素材必须配套。启动检查会拒绝旧清单。完整素材已放在

## 验证证据

本次证据位于 `doc/evidence/r3-ja-zc/`，包含实际命令日志与 JSON 结果：

| 检查 | 结果与边界 |
| --- | --- |
| Python 素材规则回归 | 7 项通过，包括奇数行裁切与归档名称固定长度 |
| 双语、存档、存储和真实素材 Rust probe | 49 项通过；真实读取新素材并逐行比对两种语言，检查全部字体 outlines |
| 无 tsukihime 特性的兼容 probe | 46 项通过；不运行真实素材检查 |
| Vita platform 主机测试 | 66 项通过 |
| 整包文件哈希 | 16,764 个文件通过 |
| 生产 C PNG 解码 | 8,258 次通过，覆盖两种语言的选区 |
| GXT 静态元数据 | 15,613 张通过边界和容器检查，不等于实机 GPU 测试 |
| 正式 Vita ARM 构建 | `vita-gxm,assets-540p,tsukihime`；包检查结果随构建回执交付 |

probe 直接导入生产语言、存档和存储模块，避免桌面整游戏对 GStreamer 的依赖。
它不模拟设置画面交互，也不把主机测试当作 Vita 实机运行。

复现命令参见 `tools/probes/tsukihime-bilingual/README.md`。素材生成工具为
`tools/make-tsukihime-ja-zc.py`，输入保留的 R2 素材、用户字体与 fontTools，
输出必须为独立目录。完整资源检查使用
`tools/verify-tsukihime-runtime-assets.py` 和由生产 C 文件编译的解码库。
